# 桌面小工具视觉审查（v1.6.2 · 卡片视觉规范 v1）

审查对象：**14 个桌面小工具**（v1.5 六件套 + v1.6 八件套）。

> **v1.6.3 更新**：v1.5 六件套（今天 / 要一起做的 / 说好的 / 还有几天 / 点滴 / 今日一句）已整组删除，
> 现役只有八件套。下文中标注这六张卡的条目仅作历史记录。
审查方式：`tools/render_widget_designs.py` 离线渲染三档尺寸设计图（格子 55 / 74 / 92dp）＋ 逐文件读布局/色板/矢量图 ＋ 对色值算对比度。**不使用模拟器判定尺寸**（模拟器屏幕密度与各家 launcher 网格差异大）。

结论先说：**14 张卡里有 13 张存在至少 1 处硬伤**，问题集中在五类——图标色没跟着文字加深、字号/内边距/按钮各玩一套、横向卡没有响应式、空态渲染成「一根横杠」、底图人物被文字/按钮压住。

## 四、真机反馈：四角「灰角」（v1.6.2 修复）

用户截图里 3×3 相伴大卡的四角各有一块淡紫灰三角/月牙。取证方法：把截图按颜色分类成字符图，
沿卡片一圈采样亮度与 RGB。结果：**页面底是 `#FAF9F7`，而卡片四边各约 6dp、四角最宽处是一圈
`#EEECF0` 的淡紫**，形状正好夹在「卡片圆角弧线」与「系统 widget 圆角」之间。

根因两条，都是自己造成的：

1. **卡片被强行缩成正方形**：`applySquareSize` 用 `min(宽,高)` 把卡片尺寸覆写成正方形，
   而桌面格子是矩形（实测格子比正方形宽/高 4–8dp）。卡片缩进去以后，四周那条缝是透明的，
   透出的是**系统给 widget 画的底色**（Android 12+ 的 `system_app_widget_background`，
   浅色约 `#F1F0F4`），不是壁纸。
2. **圆角烘得比系统圆角大**：位图圆角是短边 14%（222dp 卡约 31dp），系统自己的 widget 圆角约 16dp。
   圆角外那片透明区同样透出系统底色，于是四角变成月牙，越靠角越宽。

修法（两条一起才干净）：

- **卡片铺满格子**：删掉 `setViewLayoutWidth/Height` 的正方形覆写（布局本来就是
  `match_parent` + `layout_gravity="center"`），缝隙消失。字号仍按实例短边缩放，
  所以「内容居中、比例不扁」的观感保留，只是卡片外形不再强行正方形。
- **圆角降到系统圆角以内**：`RADIUS_RATIO` 14% → **5.5%**（148dp 卡约 8dp、222dp 卡约 12dp）。
  系统的圆角裁切会把我们这圈透明角**完整吃掉**，可见圆角由系统决定（各家 launcher 一致）；
  万一遇到不裁圆角的 launcher，5.5% 的小圆角还能兜底，不至于变直角。
- 顺带修掉线框：`frame()` 的内框圆角原来按 `r - inset` 推算，半径降到 5.5% 后会算出接近 0，
  线框四角变直角、与卡面圆角打架；改成按卡面圆角等比缩小（外框 0.62r、内框 0.42r）。

> 设计图同步：`tools/render_widget_designs.py` 新增 `SYS_RADIUS_DP = 16`，绘制卡面时按
> 「兜底圆角与系统圆角取大」裁一刀——否则设计图显示的是位图里的 5.5% 小圆角，比真机小一圈。
>
> 结论：**widget 的不透明区域必须≥系统 widget 底色区域**。只要卡片比格子小、或者圆角比系统大，
> 那圈透明区就一定会露系统底色——这类「灰角」不是圆角没画好，是露了宿主背景。


## 五、配色与排版第二轮（v1.6.4）

### 实测（先把「看不清」排除掉）

纸面实测 `#F9F4ED`、相对亮度 0.913、通道标准差 ~2（纹理很轻）。按此算对比度：

| 色 | hex | 均值对比 | 纹理最暗处 |
|---|---|---|---|
| w_ink | `#12101A` | 17.2 | 15.0 |
| w_ink2 | `#55505F` | 7.1 | 6.2 |
| w_ink3 | `#6B6577→#5C5666` | 5.1→5.9 | 4.47→5.2 |
| w_accent | `#B02F49` | 5.7 | 5.0 |
| w_her_ink / w_gold_ink / w_him_ink / w_q_ink | — | 7.3 / 6.6 / 6.6 / 9.2 | ≥5.7 |
| 白字 on w_accent | `#FFF` | 6.3 | — |

结论：**全部达 WCAG AA（≥4.5:1）**，所以「看着有问题」不是对比度，是下面三条。

### 三条根因

1. **一屏 5–6 个色相**：每张卡都自带一套「她/他/金/雨过」颜色，叠在一张卡上就成了调色盘；
   而且存在两套近似红（`#93263E`/`#7C3F39`）和两套近似蓝（`#3A5F97`/`#35578C`），肉眼分不出，
   等于既花了又没传达区分。
2. **字号只有两端**：30–36sp 与 10sp，中间空着 → 「第/天」在巨数旁边小得像符号，
   页脚、标签、按钮全挤在 10sp，整卡「要么巨大要么极小」。
3. **中文套了 0.06em 字距**：`距 下 次 见 面` 被拉开，中文本来不需要 tracking。

### 处置

- 色：**一主色**（accent）+ **三级墨** + **一个暖米浅底**；语义色退到图标层。
- 字：30–36 主数字 / 16 卡片主文案 / 12 正文与标签 / 11 说明 / 10 仅页脚；单位与标签不再低于 11sp。
- 字距：中文 0.02，数字串 0.03–0.04。
- 构图：情话卡引号与正文成组居中；3×3 引文改引用块（2dp 竖线 + 墨字），去掉粉底与蓝胶囊。


## 六、四角底色（第二次取证，v1.6.4 收尾）

第二张截图里的四角是**淡蓝**（第一次是淡紫）——同一层东西，颜色跟着壁纸走。量化结果：

| 量 | 值 |
|---|---|
| 卡片可见圆角半径 | ≈18dp（旧包 14% 位图） |
| 淡蓝区域的内边界 | ≈10dp |
| 淡蓝区域沿对角线的厚度 | ≈3dp |

结论：**淡蓝的内边界就是系统 widget 自己的圆角（固定 ≈10dp）**，外边界是卡片位图的圆角。
两者之间那圈"透明"就是系统底色透出来的地方。第一次是「卡片比格子小」的环缝，这次是「圆角比系统大」的月牙，
同一个原理：**widget 的不透明区必须覆盖系统 widget 底色的整个圆角矩形**。

- 5.5%（上一版）是**百分比**：148dp 时 8dp 没问题，但 3×3 到 222dp 就是 12dp，已经超过系统的 10dp —— 所以又露了。
- 现在压到 **3.5%**：110≈3.9 / 148≈5.2 / 184≈6.4 / 222≈7.8 / 276≈9.7dp，**全尺寸都在 10dp 以内**。
- 代价：可见圆角比系统的小一点（更"方"）。若要既圆又不露底，只能读 `system_app_widget_background_radius`
  再选对应半径的位图（多套资源），当前按"稳"优先。
